CRYPTOGRAPHY LAB · HOMEWORK 2

Two ciphers, two different weaknesses

Explore a small-key elliptic-curve scheme and the Caesar cipher, then test two attacks that exploit very different kinds of information.

Scope: this is an educational toy implementation. It uses secp256k1 curve arithmetic, but deliberately restricts private keys to a small interval. It is not a production encryption system.

01

ECC message encryption

Byte-by-byte elliptic-curve ElGamal, using a small message-point lookup table.

Let the private key be d, the public key be Q = dG, and the fresh ephemeral scalar be r. Each byte m is represented as M = mG. The ciphertext pair is C1 = rG and C2 = M + rQ. Decryption computes C2 − dC1 = M, then looks up the original byte.

Because the demo encodes each byte as mG, decryption searches only the 256 possible byte values. This is intentionally inefficient and is not a general-purpose message encoding scheme.

Run the experiment to display the public key, ciphertext summary, and recovered message.

02

Caesar cipher

A substitution cipher with only 26 possible shifts.

Letters are shifted; spaces, punctuation and letter case are preserved.

03

Statistical attack on Caesar

Estimate the shift by comparing ciphertext letter counts with typical English letter frequencies.

The attack scores each of the 26 possible decryptions using a chi-square statistic. A lower score means that the candidate's letter distribution is closer to the reference distribution. This is a statistical guess, not a proof that the text is correct.

Paste a ciphertext or use the sample to inspect the ranked candidate shifts.

Length experiment

Generate ciphertexts from the same English sample at increasing lengths and compare whether the best-ranked key is correct.

The table will report the estimated key for several text lengths.

04

Restricted-key ECC attack

Recover the private key by checking every candidate in the intentionally small key range.

The attack knows the public key Q and tests candidates d = 1, 2, …, N until dG = Q. It exploits the restricted key space; it does not break the underlying secp256k1 discrete-logarithm problem at its normal size.

The public key will be derived from the secret key; the attack will receive only the public point and the candidate range.

Discussion

Caesar encryption preserves the language's broad statistical structure because each plaintext letter is consistently replaced by another letter. The attack uses that redundancy to rank possible shifts; it can fail on short, unusual, or non-English text.

The ECC attack is different: it does not infer a secret from letter frequencies. It checks candidate private scalars against the public-key equation. With a key restricted to 1,000 values, the search is easy. With a uniformly random 256-bit key, exhaustive search would require an astronomically large number of candidates. This conclusion assumes the curve and implementation are otherwise sound; real systems can still fail through bad randomness, side channels, key leakage, or protocol mistakes.

The encryption construction here is for learning only. Real-world ECC encryption usually uses a carefully specified hybrid scheme (for example, an ECIES-style construction) with a KDF, authenticated encryption, secure randomness, and robust message encoding.
